# WCAG 2.2 AA Accessibility & UI Implementation Rules (AI Reference)

This document contains actionable development rules for rendering WCAG 2.2 AA compliant web interfaces, including specific guidance for Single Page Applications (SPAs), CSS handling, and ARIA implementation. When generating, reviewing, or suggesting HTML, CSS, JavaScript, or ARIA code, strictly adhere to these rules.

## 1. DOCUMENT STRUCTURE, SEMANTICS & SPAs
* Page Title: `<title>` must be present and descriptive.
  * SPA Routing: In Single Page Applications, dynamically update the `<title>` on every route change.
* Language: `<html>` must have a valid `lang` attribute (e.g., `<html lang="en">`). Inline language changes require `lang` on the specific element.
* Headings: Use semantic `<h1>` through `<h6>`. Do not skip heading levels (e.g., `<h2>` directly to `<h4>`). `<h1>` should identify the main content of the current view.
* Landmarks: Use HTML5 landmarks (`<header>`, `<nav>`, `<main>`, `<footer>`, `<aside>`). 
  * If multiple of the same landmark exist, differentiate them using `aria-label` or `aria-labelledby` (e.g., `<nav aria-label="Primary">`).
* Tables: Use `<th>` with `scope="col"` or `scope="row"`. Do not merge cells if it can be avoided (simplifies screen reader navigation). Use `<caption>` for the table title.
* Emphasis: Use semantic tags (`<mark>`, `<strong>`, `<em>`, `<blockquote>`) instead of purely visual CSS styling.

## 2. KEYBOARD NAVIGATION & FOCUS MANAGEMENT
* Native Focus: Links, buttons, and form inputs must be naturally keyboard focusable.
* Tab Order (`tabindex`): 
  * NEVER use `tabindex` values > 0.
  * Use `tabindex="0"` to make non-native elements focusable.
  * Use `tabindex="-1"` to make elements programmatically focusable but hidden from the natural Tab sequence.
* Focus Visibility (WCAG 2.4.13): All focusable elements MUST have a visible focus outline. Minimum 2px solid border/outline with a >= 3:1 contrast ratio against the background.
* Focus Not Obscured (WCAG 2.4.11): Focused elements must NOT be hidden by sticky headers, footers, or overlays. 
  * Implementation: Use the CSS `scroll-padding-top` or `scroll-margin` properties to ensure focusable elements clear fixed headers when tabbed into view.
* Roving Tabindex (Custom Widgets): For complex widgets (tabs, comboboxes, menus), put `tabindex="0"` on the active element and `tabindex="-1"` on inactive elements. Use JavaScript to listen for Arrow Keys to move the `tabindex="0"` and apply `.focus()`.
* SPA Route Focus: On SPA route changes, programmatic focus must be managed. Move focus to the new page's `<h1>` (which should have `tabindex="-1"`) or to a `#main` skip link so screen readers announce the new context. Do not let focus drop to the `<body>`.
* Focus Traps/Modals: When a modal opens, trap Tab focus inside it. When closed, return focus to the element that triggered it. Allow `Escape` to close the modal.
* Character Key Shortcuts: If implementing single-letter shortcuts (e.g., pressing "F" to open a search), provide a way to turn them off, remap them, or only enable them when a specific container has focus.

## 3. INTERACTIVE ELEMENTS & POINTER INPUTS
* Semantic Elements: Use `<a>` with a valid `href` for navigation (URL changes). Use `<button type="button">` for in-page actions/script triggers.
* Click Target Size (WCAG 2.5.8): Minimum hit area for mouse/touch is 24x24 CSS pixels. (Target 44x44px for AAA/best practice). Ensure sufficient padding or margin.
* Pointer Cancellation: Bind click events to `mouseup`, `touchend`, or `click`, NEVER `mousedown` or `touchstart`, to allow users to drag their pointer away to cancel the action.
* Pointer Gestures: If an action requires a complex gesture (multi-touch, swiping), provide a single-pointer, click-based alternative (e.g., Next/Prev buttons for a swiping carousel).
* Dragging Movements (WCAG 2.5.7): Provide a simple click/tap alternative for any drag-and-drop functionality (e.g., "Move Up/Down" buttons next to draggable list items).
* Content on Hover/Focus: Tooltips or mega-menus triggered by hover/focus must be:
  * Dismissible: User can hit `Escape` to close them without moving the mouse.
  * Hoverable: User can move the mouse cursor *into* the tooltip without it disappearing.
  * Persistent: It does not auto-close while the user is reading it.

## 4. VISUAL DESIGN, CSS & REFOW
* Text Contrast: Normal text requires >= 4.5:1 contrast against its background. Large text (>= 18pt normal or 14pt bold) requires >= 3:1.
* Non-Text Contrast: UI components, input borders, and informative icons require >= 3:1 contrast against adjacent backgrounds.
* Use of Color: NEVER use color alone to convey meaning (e.g., error states). Add an icon, pattern, underline, or text label.
* Text Resize & Reflow: Users must be able to zoom up to 200% (or 400% on desktop) without horizontal scrolling (down to 320px viewport width).
  * Implementation: Use relative units (`rem`, `em`, `%`). Use CSS Flexbox/Grid. Do not hardcode fixed widths.
* Text Spacing (WCAG 1.4.12): UI must not break if users apply custom CSS for dyslexia/reading aids: Line-height 1.5, paragraph spacing 2x font size, letter-spacing 0.12em, word-spacing 0.16em.
* High Contrast Mode: Do not override Windows High Contrast Mode. Use `transparent` borders on custom buttons so they become visible in forced-colors mode.

## 5. FORMS, VALIDATION & AUTHENTICATION
* Labels: Every input must have a `<label for="inputId">` or `aria-labelledby`. Placeholders do not replace labels.
* Identify Input Purpose (WCAG 1.3.5): Use standard HTML `autocomplete` attributes for personal data (e.g., `autocomplete="email"`, `autocomplete="current-password"`, `autocomplete="street-address"`).
* Error Handling:
  * Automatically detect errors and describe them in text.
  * Set `aria-invalid="true"` on the invalid input.
  * Link the error message to the input using `aria-describedby="errorMsgId"`.
* Redundant Entry (WCAG 3.3.7): Do not ask for the same information twice in a single process. Auto-fill it or provide a checkbox (e.g., "Billing address same as Shipping").
* Accessible Authentication (WCAG 3.3.8): Do not force cognitive tests (e.g., transcribing a code, complex math, or blocking paste for passwords). Support password managers and allow copy/pasting into auth fields.

## 6. ARIA & CUSTOM WIDGETS
* First Rule of ARIA: Do not use ARIA if native HTML elements (like `<button>`, `<nav>`, `<dialog>`) can do the job. ARIA overrides native semantics but provides zero behavior.
* Label in Name (WCAG 2.5.3): If a button/link has visible text, that exact text MUST be included in the element's `aria-label`. (e.g., `<button aria-label="Close modal">Close</button>` is valid. `<button aria-label="Exit">Close</button>` is a violation).
* State Management: Ensure ARIA states are dynamically updated via JavaScript (e.g., toggling `aria-expanded="true/false"` on accordions/menus, `aria-pressed`, `aria-checked`).
* Status Messages & Live Regions: For SPAs or dynamic UI updates (e.g., "Item added to cart", search results loading, form submitted), use ARIA live regions to announce the change to screen readers:
  * `<div role="status" aria-live="polite">` for standard updates.
  * `<div role="alert" aria-live="assertive">` for urgent errors.
* Hiding Content: 
  * `display: none` or `visibility: hidden` hides from EVERYONE (visual and screen reader).
  * `aria-hidden="true"` hides from SCREEN READERS ONLY (use for decorative icons).
  * `.sr-only` (CSS visually hidden class) hides VISUALLY ONLY, keeps for screen readers.

## 7. MULTIMEDIA, ANIMATIONS & MOTION
* Audio Control: Any audio playing automatically for >3 seconds must have a pause/mute control.
* Auto-updating Content: Carousels, sliders, or auto-updating feeds must have a Pause/Stop button.
* Reduced Motion: Honor the OS-level user preference for reduced motion. 
  * Implementation: Wrap non-essential animations in CSS `@media (prefers-reduced-motion: no-preference)`.
* Flashes (WCAG 2.3.1): Absolutely NO UI elements or videos may flash more than 3 times per second (seizure risk).
* Audio/Video Alternatives: Provide `<track>` elements for captions on videos. Provide descriptive transcripts for audio-only content.
